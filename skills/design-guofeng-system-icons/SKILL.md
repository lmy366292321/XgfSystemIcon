# 新国风功能图标设计

## 开始执行

只读评审既有图标时，先进入下方“批量任务”，读取当前任务要求和对应验收规范，不启动图像生成或编辑。Windows 已部署环境优先按 [本机固定运行入口](references/local-runtime.md) 调用现有 Python；其他环境使用已具备 Pillow 的明确解释器。

1. 读取 [设计规范](references/design-standard.md) 和 [参考图库索引](references/reference-library.md)。先按图库索引选定10张正式参考并实际查看，建立本任务的组内比较基准；再按功能、材质和轮廓选择画风输入；结合内容参考时，实际图像输入仍按需共1–3张，并保留正式R画风依据，不能只读文字或一次把整库全塞入生成。
2. 先按 [完整组合区域流程](references/composition-layout.md)确定组件、可见区域和摆放，再读取 [画面控制卡](references/visual-control.md) 与 [交付与失败处理](references/delivery-review.md)，填清主次物件、参考分工、必须保持/允许调整/禁止出现，以及120px辨识与组合适配条件；普通单图任务同样执行，默认将组合位置写入PNG留白并将UI额外补偿归零。按需要查看对应局部裁切；文字不能保证像素级一致。
3. 明确功能操作、主体、辅助语义和必须保留的元素。新选物时查[物品词库](references/object-content-library.md)，按选定类型核对[结构卡](references/object-structure.md)，再用[物品构图方法](references/object-composition.md)确定状态、识别面与主辅关系；已有主体的精修只查相关项，不另行换物。信息足够就直接制作；只有功能语义或缺失的关键组合尺寸会影响设计时才询问缺口。不要为常规配色、导出或可逆修改重复索要许可。
4. 区分参考用途：用户原图负责主体保真，界面图提供内容语义及组合关系，精确布局优先取组件记录，内置图按图库明确授权的范围借鉴画风、材质、结构或相对比例，不把内容和全部参数一起照搬。C类内容参考仅用于注明的物品、结构、构图，不是画风基准，不占固定10张正式R对照名额；配色仍单独指定。用户本次明确要求优先于默认规范。
5. 使用当前环境的图像生成/编辑能力及其技能；缺少能力时明确说明，不以SVG、代码绘图或文字方案冒充已生成图标。不要仅因工具限制擅自切换付费API。

## 固定工作流与交付判定

制作、修改及只读验收均执行 [配色计划与固定审核流程](references/palette-workflow.md)。单图也使用清单。先用 `review_workflow.py start` 封存主辅色与参考分工；制作再记录实际生成输入，并按[色彩空间与导出记录](references/color-space-export.md)采集原始返回文件、验证导出；旧任务只读补采集，不倒填历史。依次执行文件检查、八项视觉审核与整组配色检查、第二遍复查，最后运行 `check_batch.py`。每步保存新记录，不能跳步或倒填历史。

**只有最终 `delivery.status=pass` 且退出码0，才可称“资源交付审核通过”。** 机器子项通过、对照生成成功或历史用户接受均不能替代。缺项、失败、过期证据仍可交付明确标注状态的候选稿；不得称完整通过。完整组件适配纳入现有视觉项，不能再整体排除UI组合关系；配置和资源须人工核对，现有脚本不自动评判遮挡。工程及用户接受另列。

风格统一以线条、明暗、色块与细节层级建立。新作不默认青绿，不将同主色设为系列约束；按功能、材质和整组分布设计主辅色。同色有语义或用户依据时允许，不强迫彩虹分配。已确认原图配色仅在获得改色授权时调整。

## 默认规格

- 1024×1024、8位RGBA透明PNG、sRGB；默认先在高清完整画布中落实组合定位，再导出120×120透明PNG。零补偿接入及双尺寸取整例外见[组合输出规则](references/composition-layout.md#输出与双尺寸关联)。
- 默认文件安全区为中央820×820，四边至少102px透明留白；它不等于完整组件的可见区域。按组合关系设计留白，冲突按组合流程处理，实际测量而非只信提示词。
- 等比例缩放；完整包围框最大边通常770–820px，根据视觉重量校准。不能拉伸，也不能把几何框相同说成视觉大小一致。
- 唯一主光来自左上10点钟方向；右下暗面。柔和大色块，少量香槟金，无碎高光、厚重金属感或颗粒噪声。
- 暖棕或同色系深描边，内部线更细更浅；6px外线/3px内线仅是1024创作起点，不宣称机械等宽。
- 图标文件不加文字、按钮底板、背景场景、外发光或无关装饰；组合预览使用独立的真实配套资源。统一画风不等于统一内容。
- 仅以120px进行小尺寸视觉验收，不擅自增加74/96px门槛。

## 制作与验收

1. 用一句话确定功能语义，按已绑定的完整组件区域设计一个主要物件及必要辅助物。旧图调整保留识别主体。
2. 用规范中的创作或定向精修模板出图；按工具要求先查看本地参考。多图任务逐项保留功能差异。
3. 实测输出。必要的等比例导出和透明画布定位遵循当前环境工具规则；不得声称仅靠生成已实现精确规格。
4. 检查透明边缘。不要盲目二值化、统一删除小组件或填实半透明；低透明度像素也可能是正常抗锯齿。已证实为噪点才清理。用 `scripts/alpha_safety.py` 区分低alpha残点与主体越界；新候选的可选残点归一化及可重放证据见[色彩导出](references/color-space-export.md#远离主体的极淡残留诊断与可选导出归一化)，不放宽安全区。
5. 对1024文件执行只读检查（需要Python 3与Pillow）：

   ```bash
   python scripts/check_icon.py /absolute/path/icon-1024.png --preview /absolute/path/icon-120.png --layout /absolute/path/layout.json --require-srgb
   ```

   上述为普通任务默认命令，批次条目也绑定同一布局；缺布局或UI额外偏移非零不能整体通过。已确认边界或双尺寸例外改用`--geometry /absolute/path/geometry.json`提供布局及变换链，按[任务几何合同](references/composition-layout.md#任务几何合同与只读验证)分列默认结果与任务检查。批次条目绑定同一合同。本机使用固定入口的`check-icon`操作，避免调用不带Pillow的默认Python。脚本只读，分别报告真实PNG位深、文件/布局边界、色彩标识与双尺寸关联；默认派生算法为Pillow LANCZOS。非零退出查看具体失败或未验证项，不自动修图。严格sRGB标识检查及旧资产例外见设计规范；脚本不判断画风、功能、噪点、光源或描边，也不证明上线合格。
6. 按 [120px固定对照流程](references/qa-120.md)记录参考、文件版本和逐项结果。实际查看120px浅底 #F4EDE1 和深底 #293139 的对照，与固定的10张同组正式参考按实际120px画布分行对照，待验图及修改前图另列，不占10张参考名额。检查功能识别、视觉重量、重心、结构、光源、描边、异常线点及主辅色层级；另查整组主色重复、关系组及完整组合中的遮挡和固定摆放。没有查看就记未验证。
7. 按交付与失败处理逐项核销目标和保持项；关键失败不判合格，同一目标连续两次未改善须先改变方法。只针对失败项修正。交付高清、120px和绑定最终版本的图标/组合对照，遵循环境保存规则。只要求方案时不擅自生成图片。
8. 保留本次简要任务记录与实际调用次数，主动评估入库；简要回报哪些规格实测通过、哪些仅视觉检查、哪些未验证；未做引擎导入/图集压缩/真机检查，不说线上验收通过。

## 成果入库

每次图标完成、修改通过检查或收到用户确认后，按 [参考图库的成果入库规则](references/reference-library.md)主动评估并给出入库建议，注明用途与状态。已确认成果进入参考库不等于其设计选择升级为全局规则；日常合格成果沉淀不受“暂不扩充图库”的无目的搜集限制。

## 批量任务

多图制作、批量交付或复查时，读取 [批次清单与只读验收](references/batch-review.md)。以预期项目清单关联高清、120、控制卡、参考和报告，运行最终交付关卡 `scripts/check_batch.py`；用 `scripts/build_qa_sheet.py` 生成固定10参考与候选另列的120px浅深底对照。只写新报告与检查图，不改写输入。批量结果不能替代实际视觉、用户接受或工程验收；其他导出库的历史证据不冒充本次Pillow复验。

涉及不同材质或物件类型时，再按 [跨物件画风验收](references/style-transfer-review.md) 区分共用画风、允许差异与内容锁定；先检查代表组，再覆盖全批及易混淆组。关系面板是固定10参考对照的补充，不提供自动画风评分。

## 使用反馈与维护

收到使用反馈或用户要求沉淀经验时，读取 [反馈闭环](references/feedback-loop.md)；查阅并更新相关 [案例记录](references/feedback-records.md) 和 [规则变更记录](references/rule-changes.md)。普通出图只读取与当前问题相关的记录，不加载全部历史。先实际验证修改效果，再决定规则更新；把单图要求、候选结论与生效规则分开。用户确认单图不等于批准全局标准；未经跨案例验证的视觉经验保留为候选。 完整八项v1–v5的反馈、修改效果、误判更正及本图要求隔离见 [功能入口迭代案例](references/privilege-icons-feedback.md)；先核销最终目标，再决定经验能否升级，不把同批多图当独立跨案例。
