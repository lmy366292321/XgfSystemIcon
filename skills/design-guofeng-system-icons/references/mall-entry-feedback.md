# 商城双入口：视觉重心、等级与项目画风

适用于同功能不同等级入口的制作和复查；本记录不新增正式参考。用户于2026-10-23要求先更新技能，再继续设计。

## 已发生的反馈与证据边界

- 首轮用户指出：“视觉尺寸感受不统一，而且都有点小，没有张力，建筑感受也不太符合古风项目预期，非重要内容少部分可以被名称板遮挡。”
- 厚瓦、粗柱的v4建筑稿随后收到：“视觉感受不像女性向游戏内容”。这是本项目用户评价；不能推成所有女性用户的审美规律。
- 轻柔v5收到：“视觉中心太靠下了”。两枚整体在120px上移6px、高清上移51px后，像素保持及几何检查通过，用户仍反馈：“还是偏下，而且高级的没有体现出比低级的更高级，反而是低级的更亮更吸引人”。因此上移操作完成不代表视觉重心目标达成；此前技术通过保留，视觉目标重新打开。
- 本地证据：output/mall-soft-v5-20261023、output/mall-v5-up6-20261023的1024、120、qa及records；均相对本次项目根目录。改稿v6仍是未获用户确认的候选，不记录为改进成功。

## 制作和复查方法补充

1. **先定义关系，再分别绘制。** 对高级/初级等关系组，在控制卡写明共同身份、应区别的等级、拟用的材质/工艺/结构/主色层级依据。单枚精致或名称正确不足以证明等级成立。用实际120px、相同圆底和名称板位置并排观察；先看不含名称文字的关系面板，再看完整组件。分别记录“同类可识别”“等级可区分”“高级吸引力是否被初级反超”，不把色差当作等级证据。
2. **重心是完整组件中的视觉判断。** 包围框、alpha重心和固定上移量只作诊断。看上部轮廓、主体明暗面积、下部柜台/货物及名称板共同形成的重量；在同条件前后图上核销偏下反馈。连续微移未解决时重新检查上下体块分配和名称板关系，不继续把上移量当作成功结论。允许非关键部分遮挡时沿用已有许可，关键识别面仍保留。
3. **项目画风不靠单一标签替代。** 古风建筑需同时核对屋檐/柱体/格窗的结构与既有参考的线条、色块和材质层级。增加瓦顶不自动满足项目预期；降低饱和度或整体漂白也不自动成为女性向。保留清晰主色、柔和但可读的明暗与有选择的精细工艺，再与正式参考比较。不能从本例推出统一粉紫、加花、禁木材或一律细柱。
4. **等级提升与整体变暗分开。** 可以尝试更清晰的主色、材质差异、少量精细边饰或主体结构；不要默认压暗初级来制造相对优势。高级更亮/更饱和/更复杂都不是通用必要条件，最终以成组视觉语义判断。具体方法须在成图验证后才记为本例有效。
5. **失败核销不互相替代。** 清除透明残点、尺寸一致、像素不变、安全区通过不能关闭体量、女性向、重心或等级反馈。两遍审核都绑定最终文件和同条件组合图；用户否定自评时保留过程并修正状态。

## 适用范围与验证状态

上述是现有目标/保持项复查的细化，不是新增美术配方；流程补充生效，改善生成质量的效果未验证。紫金/杏色、具体平移像素、遮挡深度仅属本任务。后续3个相关任务或再次复发时检查是否减少误判；造成额外负担而无收益时合并或缩小条款。用户确认、完整资源审核和工程接入分别记录。
