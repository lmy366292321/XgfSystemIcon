# 完整组合区域设计与留白

普通新增图标、单图精修、批量制作及只读评审均适用。先确定使用时的完整组件，再设计图标的可见范围、体量与留白；不等到用户提供适配反馈才检查组合。本文规定通用流程，具体底框、名称板和坐标由任务配置提供；[好友底栏案例](bottom-tab-20261021.md)单独记录该组的布局、最终文件及技术边界。

## 设计前确定组合

优先读取已有项目布局、组件资源和已确认摆放记录；截图可以确认视觉关系，不能单凭缩放截图认定精确坐标。控制卡绑定一份组合配置的路径与SHA-256，包含：

- 图标图层尺寸与完整组件范围，坐标原点、单位、缩放、锚点及对齐基准；区分图层矩形与可见像素包围框。
- 实际使用的底框、名称板、文字及覆盖物的文件版本、尺寸、位置、层级、裁切方式；红点或选中态只在组件确有这些内容时纳入，不凭空添加。
- 主体和辅助语义应处的可见区域、允许出框区域、被名称板覆盖的区域，以及必须露出的关键轮廓。涉及相邻入口时使用已知的真实间距。
- 哪些值来自确定布局，哪些只是待核实的预览估计；默认由PNG内容定位承担组合补偿，UI额外偏移为(0,0)，仅记录用户明确指定的其他接入例外。

独立使用且没有底框、文字、覆盖物的图标，也应明确完整组件就是其使用区域，无须虚构配套部件。缺少影响构图的关键尺寸时，先完成已有资料可支持的语义和参考规划，再只询问缺口；暂定组合须标为暂定，不能据此宣称真实适配通过。

## 留白与固定摆放

图标图层、图像内容、完整组件是三个不同范围。120×120默认是图标图层尺寸，圆框和名称板组合可以超出它；不要为塞入120框而缩小整个组合，也不要把底框和名称板烘焙进透明图标。

设计规范中的透明安全区继续作为默认文件边界，不能代替组件的可见区域。留白根据组合中的视觉重心、覆盖关系和主次物件布局设计，不要求上下左右机械相等；也不能靠预览临时挪图掩盖实际PNG定位。已确认组合需求与默认安全区冲突时，绑定本任务的几何合同，记录布局依据、允许边界和实测留白，不为满足默认102px而擅自缩小或重新居中。默认检查结果保留；任务边界按合同另判，不能改写默认失败或历史报告。未绑定有效合同仍执行默认规则。

同组先固定图标图层与底框、名称板的共用位置和缩放。修改心形、星形等局部时，锁定人物、整图位置、画布和组合配置；不能每个候选各自紧裁、居中、缩放，借此制造改善。确需调整整图摆放时，作为单独变更记录并重新比较全组。

普通任务默认将已确认的组合位置落实到PNG透明画布内，并将UI额外位置补偿设为(0,0)；不再交付必须额外挪图才能复现的PNG。归零的是相对组件基准锚点的补偿，不是把按钮、圆框、名称板或页面坐标全部移到原点。位置只计算一次，禁止PNG已移位后仍保留原UI补偿；用户明确指定其他接入方式时记录例外。要求精确比例、像素位移或人物像素不变时，沿用[控制卡的迭代规则](visual-control.md#迭代规则)，不把生成提示当成实测。

## 输出与双尺寸关联

新任务先按组合可见区域在高清完整画布内确定内容坐标，再统一导出使用尺寸；图案、底框、名称板继续分离。需要转换既有布局时，在新文件上执行有记录的确定性平移，保持画布、图案大小、颜色与人物/辅助物相对关系，不紧裁铺满、不重绘。移动前检查越界，保留正常半透明边缘；不能悄悄丢弃被移出画布的非透明内容。

默认120版仍从已定位的完整1024稿导出。遇到既有布局要求使用尺寸精确整数移动、对应高清位移却为小数时，明确主交付尺寸、各尺寸坐标/算法与取整误差。只有任务的保真或精度要求需要时才单列两条变换链；不能把分别搬移后的两个文件伪称为直接缩放派生，也不将本案6px/51px推广为通用值。当前几何检查支持完整画布缩放及整数平移；独立双分支先核对原1024/120确为同一完整画布缩放对，再重放各自平移。不支持的裁切、非整数平移、蒙版或生成处理仍记未适配，不能写成无变换。

交付记录绑定选定图案源文件、新PNG、导出顺序及各自哈希，列明图内位移、UI零补偿、裁出像素数/透明度和需要继承的技术限制。默认另存版本；只同步技能或用户停止图像处理时，不补做图像变换。

### 任务几何合同与只读验证

所有任务都绑定布局。普通任务复制[布局结构模板](../templates/layout.example.json)，填写真实组件范围、资源、坐标和状态，单图命令传入`--layout layout.json`，批次条目填`layout: {path, sha256}`，控制卡引用同一文件。独立图标可明确无配套部件；模板的示例状态不代表真实适配确认。普通路线仍检查102px安全区及完整1024→120直接缩放，不需要为布局检查创建几何例外。

布局检查要求`icon_layer`为120×120、scale=1、相对组件基准锚点的offset=[0,0]，核对布局和嵌套资源哈希；普通与例外路线均纳入批次快照和审核绑定。缺布局时文件诊断保留，但`layout_check/layout`为未验证，单图整体、机器关卡及交付均不能通过；非零偏移、错误图层或失效绑定判失败。配置通过只证明记录一致，不证明引擎实际偏移或视觉适配。

需要已确认的布局边界或双尺寸例外时，填写[几何合同模板](../templates/geometry-contract.example.json)，不能直接把模板的待确认状态改成已确认而省略真实依据。合同内的`layout`可直接提供布局绑定，无须再重复一份；若同时提供独立`layout`，必须指向同一文件且哈希有效，冲突时拒绝通过。

- 合同固定`schema_version=2`、`kind=icon_geometry`，记录Pillow实际版本和重采样算法。所有路径相对合同文件；`layout`内部资源路径相对布局文件。配置、确认依据、源图、输出均用path/SHA-256绑定。旧v1合同须另存升级记录并补齐目标/取整依据，旧报告保留；不得为迁移记录重新导出最终PNG。
- `confirmation`包含`status=confirmed`、`scope`及`basis`文件。脚本只核对明确状态及证据完整性，不认证人的授权，也不判断组合美观。`layout.icon_layer`明确120×120、scale=1及相对组件锚点的offset=[0,0]；其他部件坐标不归零。
- `allowed_bounds.master/preview`为各自画布内允许的非零alpha范围`[left,top,right,bottom]`，右/下为开区间。依据已确认布局填写，不能看见失败后自动扩大；默认四边102px结果继续保留。alpha=1也计入边界。
- `outputs`绑定最终1024/120；`chains.master/preview`分别绑定`source`和有序`operations`。`resize`仅做正方形完整画布到1024或120；`translate`使用整数`offset`，保持画布和保留区域RGBA，不混合、不紧裁、不改色彩声明。比较实际RGBA，仅在双方alpha都为0时忽略不可见RGB差异；脚本只在内存重放，不保存PNG。
- `mode=master-to-preview`、`primary=master`：高清链可先定位，120链必须从最终高清完整缩放一次。`mode=independent-translations`：各自从已核对关联的原1024/120仅做整数平移；必须指定`primary=master|preview`、主尺寸像素单位的整数目标`target_translation=[dx,dy]`和`rounding_method`。先把目标按画布比换算为另一尺寸的精确有理数，再按明确方法取整；主分支累计位移必须等于目标，另一分支必须等于该取整结果。每个分支仍逐像素重放，不能仅凭两份独立记录证明关联。
- `rounding_method`支持`nearest-half-away-from-zero`（最近整数，恰好半数时远离0）、`floor`（向负无穷）、`ceil`（向正无穷）、`toward-zero`（向0）。负数同样按此定义，不用含糊的“round”或依赖语言默认。报告自动计算`rounding_error_at_120=高清累计位移×120/1024−120累计位移`；合同可额外声明该误差作交叉核对，但误差值不能替代目标和取整校验，也不能放行任意错位。
- 平移默认要求裁出非零alpha为0。若历史成品已发生损失，`expected_clipped`如实记录`count/max_alpha/alpha_sum`；数值不符判失败，数值符合但没有明确损失接受依据仍为未验证。确有授权时另绑定`loss_acceptance`的confirmed/scope/basis；不能由普通布局确认推导像素损失已接受。

普通单图使用`check_icon.py master.png --preview preview.png --layout layout.json`；例外使用`--geometry geometry.json`提供其布局及变换链（需色彩声明时均加`--require-srgb`）。`file_check_pass`仅表示文件路线结果，`overall_check_pass`还要求布局通过。默认结果与当前任务结果分列；格式、空图、错误绑定或重放差异不能被布局例外豁免。

批次条目增加`geometry: {path, sha256}`；`export`的library/version/resample须与合同一致，complete_canvas=true、alpha_handling=geometry-contract、color_conversion=none。清单、控制卡和审核绑定须更新；规则或嵌套输入变化使旧意见过期。实际色彩处理发生在定位前，按[color-space-export.md](color-space-export.md)连接原色彩记录，不把定位后的文件倒称原始生成源。

## 同条件组合检查

沿用[120px对照](qa-120.md)的十参考浅深底检查，同时查看当前任务图标的完整组合：使用真实底框和名称板、同一布局配置、同一观察比例；图标图层保持120px，面板为完整组件留足空间，不裁掉名称板。选中态等使用态存在时按已有资源检查；替代背景或字体明确标为预览近似。最终对照必须直接使用交付PNG并将图标UI额外偏移设为0，不能继续靠CSS或引擎补偿演示效果；从旧布局转换时，对比“原PNG+旧补偿”与“新PNG+零补偿”，报告实际像素差异，不能仅凭目视或参数推定一致。

组合证据在首遍与第二遍视觉审阅正文中绑定：布局配置、底框/名称板等资源、前后图及最终选定文件的路径与SHA-256，并记录实际观察的组合图或HTML及其哈希。沿用现有八项意见，不再另设一套重复评分：

| 现有项目 | 增补的组合判断 |
|---|---|
| semantics | 名称是否辅助区分，辅助符号是否仍能辨认 |
| weight | 同组主体体量、视觉重心及与底框/名称板的承托关系是否协调；零遮挡或外框等大不能单独核销大小与贴合感 |
| structure | 底框/主体/名称板遮挡是否合理，关键轮廓是否被截断或粘连 |
| keep | 固定摆放、人物和其他保持项是否漂移 |

相关组合证据不足，对应项目记未验证；发现问题记失败，不能仅在展示用的other_states里留一句话后判完整通过。其他四项继续按原规范检查。用户指定裙摆/架脚等不得遮挡时按本任务执行；允许非关键底边覆盖的其他任务另行判断，不把某图的零遮挡、位移或缩放系数推广成全局目标。

普通布局和几何合同都会核对布局文件描述符、嵌套资源与UI零补偿，并纳入输入快照与审核版本绑定；例外另外核对允许像素边界、变换链、主尺寸目标及取整。真实遮挡、关键轮廓、视觉重心和确认依据的适用范围必须实际审阅，不能由几何通过推断。配置、资源或选定版本变化时更新控制卡绑定并重新审阅；静态组合通过不代表引擎或真机通过。

## 最终版本与停止边界

按[反馈闭环](feedback-loop.md)保存用户选定的具体文件和哈希；参数目标、生成候选、用于对照的候选和最终选定稿分别记录。用户选择旧候选时，不用“最后修改时间”替代选择依据。若现有组合对照使用另一版，明确它不能证明最终稿的组合效果；用户要求停止或只同步技能时，登记未复验，不能以补齐流程为由继续处理图像。
