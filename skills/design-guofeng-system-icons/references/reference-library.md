## 选择顺序

1. 从功能语义选一个内容依据：本次用户图或界面优先，其次上述相关主图。
2. 从材质/轮廓选1张主画风参考，必要时再选1张辅助图。通常总计1–3张，不把9张全部塞入生成。
3. 对风险部位查看下一节对应局部图。局部图用于观察，不一定全部作为生成输入。
4. 新图主体没有同类参考时，组合最接近的材质和轮廓参考，并说明迁移范围；不能声称已有完全匹配参考。
5. 用户明确批准某图/局部后，记录具体批准范围和日期再升级其状态。不得把“批准色彩”扩展为“批准全部结构”。

示例：花茶选R02＋R01；新礼盒选R04；开箱选R05或R06＋R04；消息入口选R09＋R01；有青瓷印章的纸类功能选R08＋R01。内容不要强行相同。

## 成果入库规则

每次交付及收到用户确认后主动评估，不能等用户再次询问是否应入库。

| 成果状态 | 处理 |
|---|---|
| 已完成检查，用户尚未确认 | 作为候选案例保存，说明待确认范围，不冒充正式参考 |
| 文件规格与120px检查通过，用户明确确认对应版本 | 主动建议纳入正式参考，说明新增代表性和可借鉴范围 |
| 已确认但与现有参考高度重复 | 保留为已验收成果，说明无需增加默认参考；优于旧图时可建议替换 |
| 用户确认但检查未完成或仍有失败项 | 分开记录确认与验收状态，补齐检查或明确例外，不能直接标为完整验收通过 |

- 优先沉淀新增主体类型、材质或构图的代表性成果。建议格式：“建议入库：版本/文件；用途；补足的类型；限制；检查与用户确认依据”。
- 入库建议与实际入库分开记录。已有明确入库授权时直接执行，不重复询问；没有时先给出具体建议，不声称已入库。
- 实际入库时保存准确的已确认版本，登记来源、文件哈希或资产提交、用户确认日期/范围、120px检查证据、参考用途和限制；更新索引并同步安装副本与GitHub。不能仅靠另一个环境无法访问的链接声称参考文件已部署。
- 入库不要求先证明跨案例通用规则有效：成图可以作为限定用途参考，视觉经验仍可保持候选状态。人物造型、配色和头身比例不自动推广。
- 新增参考使用下一个未占用ID，保留已有R01–R09；替换旧参考时记录替代关系与历史版本。图库增长不改变每次按任务选择1–3张的原则。
- “暂不扩充图库”仅限制无目的搜集参考或专项扩库，不阻止日常已验收、已确认成果的评估与沉淀。
