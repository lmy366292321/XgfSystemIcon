# 跨物件画风一致性验收

用于同批图标包含不同物品、材质或组合复杂度时。规范仍以 [design-standard.md](design-standard.md) 为准，参考授权以 [reference-library.md](reference-library.md) 为准；本流程补充比较方法，不另设美术分数或通用比例。

## 分开三种约束

在 [控制卡](visual-control.md) 写清共用画风、本物件允许差异、可能误带入的内容。

| 类别 | 判断方式 | 不应得出的结论 |
|---|---|---|
| 共用画风 | 对指定主参照看色块概括、细节层级、左上受光、外内线层级与整组视觉重量 | 像素框相同即体量相同；所有物件必须同色同形 |
| 材质允许差异 | 纸面哑光；丝绸随折面变化；玉石可有连续反光；瓷器允许曲面反光。逐项写明来源及限制 | 玉比纸亮即失败；把某件器物的高光复制到整组 |
| 内容锁定 | 逐条查功能、关键轮廓、连接、主次和禁用项；需要时查看用户原物图 | 只要画风相似就能改掉货币缺口、道具身份或功能符号 |

花纹、蝴蝶结、金边不是自动失败项。核对它们是否来自本任务设计或物件身份，是否抢占功能层级；没有生成过程证据时只能记“内容误迁入风险”，不能断言模型复制了某参考。金色饰边与深色轮廓分开判断。

## 固定条件与检查顺序

1. 锁定同一份批次清单、10张正式参考及其用途。按 [qa-120.md](qa-120.md) 实际查看浅深底完整120px总览，候选不能占参考名额。
2. 选少量能暴露差异的代表物件，例如单卡、柔软包袋与玉组合、开箱多物组合。先试走记录方法，再覆盖全部项目；代表组通过不能替代全批。
3. 对容易混淆或复用同物件的入口建立关系组。图中仅标ID，先记录看见的主物与符号，再核对名称/点击目的。已看过任务的审阅者不能将此步骤称为盲测或玩家研究。
4. 以控制卡指定的体量、明暗、描边主参照判断；其他图只用于其批准用途。高清只定位细节，回到120px核对它是否影响辨识，不能用高清能看见替代120px可辨。
5. 将问题区分为画风偏差、语义偏差、结构偏差或证据缺口。每项给观察位置、参照、允许差异理由和改动建议，同时写保持项。纯偏好不冒充现行规范失败。
6. 复查曾误报通过的维度与保持项。独立复核不可用时，单独第二遍查看并标“同一审阅者复查”；结论分歧保留原因。审阅意见绑定规则、控制卡、图片与对照证据；文件更新后按批量规则失效。

## 关系组要回答的问题

- 同系列不同权益：只有任务要求共用基础形态时才核对同卡型；还要分开查长宽、厚度、装饰位置和各自功能符号，外轮廓相近不等于形体已自然。哪些权益合理依赖名称？
- 相同物品、不同入口：关键身份特征是否保持？承载物能否区分入口，并有本任务语义依据？不能只因参考中有书册/箱子，就把它当中性容器。
- 不同奖励、相似载体：主物是否被载体或花纹压小？两入口是否容易混淆？根据任务检查，不一律禁用册子、碗或礼包。
- 多奖励组合：分别写出看见的物体、推断的奖励类别及名称依赖。布料存在不自动证明衣装可辨，饰牌存在不自动证明称号含义，开箱轮廓不自动证明惊喜感。

以上为检查问题，不规定各图同色同形。完整前后证据及只适用本图的解决方法见[F-20261021-002](privilege-icons-feedback.md)。

主色重复、辅色挤占主体、材质颜色混同须在整组配色审核中单列；遵循[固定流程](palette-workflow.md)，不得只以线条一致核销配色目标。

## 最小记录与判定

复用批量 `visual_review.items` 的八个维度（含palette），不另造一个总分。`pass` 表示该条件下本维度未发现阻断偏差；`fail` 必须说明违反的要求与可观察位置；`unverified` 写明缺哪项证据。总体有关键失败即不通过；允许依赖名称的功能不因无法读出全部规则而自动失败。

每个维度至少保存 `status`、`observation`、`location`。另保存主要参照/用途、差异理由、偏差类别、建议改动和保持项；关系组正文可以集中写一次，由逐项引用。把“已确认的文件事实”“视觉判断”“原因假设”“待验证内容”明确分开。

分别记录中间变化与原目标：层次分开后仍查活动氛围，细节减少后仍查颜色/材质，附属物删除后仍查结构，体量数字变化后仍看核心主物。观察到变化但无法证明目标时写未验证，不用代理指标换取通过。

改动建议写成“缺陷 → 局部改法 → 保持项 → 相同条件复查”。先处理关键功能或身份，再校准主物体量，最后收敛细节。不要把所有图统一放大、统一加粗或统一降低饱和度作为通用修复。实际修图遵循当前授权；只读验收不修改原图。

## 校准与后续验证

用已见过的8项v1做代表组、全批和关系检查，只证明流程可执行，并形成针对现有稿的视觉意见。它们都属于方法校准样本，不能改名充当独立测试集。

下一次已授权的真实制作任务，在看到输出前锁定控制卡、参考与成功条件，检查新物件的迁移。若又用它调整方法，则将其改记为校准案例。按已有反馈闭环比较具体偏差、保持项退化与修改次数；在没有新稿和实际比较前，不宣称画风已改善或重绘减少。连续失败按 [delivery-review.md](delivery-review.md) 处理。
