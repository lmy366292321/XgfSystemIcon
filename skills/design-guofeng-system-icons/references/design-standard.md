## 1. 使用方式

将本文与按图库索引选出的1–3张相关高清图标一起作为设计输入。R01–R09当前9张完整参考已于2026-10-14获用户明确确认，作为正式视觉基准；具体版本与范围见图库索引。先确定功能语义及[完整组件区域](composition-layout.md)，据此安排主体和留白，再应用统一美术规范并进行尺寸与120px组合检查。

本文是可复用设计与交付规范，不是“所有生成结果自动合格”的保证。提示词中的尺寸、描边与光源要求必须在结果中核实。只提供本文、未提供参考图时，应标记为近似复用画风。

## 2. 设计目标与边界

- 面向新国风女性向古风手游：清雅、柔和、精致，兼顾功能辨识。
- 同组图标统一画风、明暗逻辑、描边视觉粗细、主体视觉重量及交付规格。
- 不要求所有图标使用相同物品、相同构图或相同主色。
- 在120×120px显示时，先看懂主物，再看见辅助语义；不要依赖细纹辨识功能。
- 已有图标改版优先保留原主体和关键识别轮廓，不随意替换物品。
- 新增图标从功能界面提取核心物件；界面中的占位图标和临时文案不直接作为设计依据。
- 不把“画布一致”“包围框一致”“视觉大小一致”混为一谈。

## 3. 统一美术规范

| 项目 | 要求 |
|---|---|
| 画风 | 概括而精致的2D手绘游戏道具，清楚的大色块，少量柔和明暗 |
| 气质 | 轻盈清雅、有温度，避免厚重金属、过度写实与塑料高反光 |
| 配色 | 按功能、材质及本批分布选择主色、辅色、点缀色；保持色块层级与协调，不设默认色相 |
| 对比 | 低饱和不等于低辨识；主物、辅助物及前后结构应有足够区分 |
| 材质 | 按物品区分纸、瓷、丝绸、羽毛、金属；金色只作必要点缀 |
| 视角 | 道具优先轻微俯视的三分之四视角；青鸟等生命主体以结构正确与轮廓清楚为先 |
| 光源 | 唯一主光来自画面左上方约10点钟方向，主要暗面偏右下 |
| 高光 | 连贯、克制；不使用密集亮点、强烈轮廓光或四面同时发亮 |
| 外轮廓 | 暖棕或同色系深色线，连续平滑，与整组视觉粗细一致 |
| 内部线 | 比外轮廓更细、更浅，仅保留必要结构 |
| 装饰 | 只服务识别与材质，优先删去碎花、珠串、长流苏、散落花瓣 |
| 背景 | 真实透明，不附场景、按钮底板、底色或外部投影 |
| 文字 | 图标本体不带标题、功能名、水印与说明文字 |

### 描边的使用口径

创作时可用“1024画布外轮廓约6px、内部线约3px”作为起始提示，但这不是当前图标已逐像素测得的等宽结果。

最终以120px下的轮廓视觉粗细为主要标准。手绘线条允许自然收笔与宽窄变化，不允许某一张明显黑粗、某一张明显淡薄。金色装饰边不能误算作轮廓描边；不通过额外叠一圈黑边掩盖不一致。

## 4. 画布、主体大小与安全区

| 项目 | 统一规格 |
|---|---|
| 高清交付 | 1024×1024px，PNG，8位RGBA，sRGB |
| 使用尺寸 | 默认图标图层120×120px透明PNG；完整组件范围由任务配置单独确定 |
| 安全区 | 默认文件内容限于中央820×820px；组件可见区域与名称板遮挡另按组合配置检查 |
| 最小透明留白 | 默认四边不少于102px；已确认组合定位的例外须记录实测范围，不以重新居中抹去布局 |
| 主体缩放 | 等比例，不横向或纵向拉伸 |
| 主体大小 | 通常将完整可见包围框最大边控制在770–820px，再做视觉校准 |
| 对齐 | 按完整组合重心和锚点将内容位置写进PNG，UI额外补偿归零；独立使用时以自身区域为基准 |
| 附属元素 | 丝带、尾羽、信笺等均计入安全区，但不能独占过多尺寸导致核心主体过小 |

默认安全区的坐标口径：以左上角为原点，像素索引0–1023，可见内容限制在x、y各102–921范围内；使用右/下边界不包含在内的包围框时，上限为922。

### 视觉大小校准

1. 在同一组合配置中先比较核心主物的体块、明暗重量和识别面积。
2. 再比较完整轮廓，而非让所有长边机械相等。
3. 疏朗主体可以适当放大，实心方盒等高视觉重量主体可以略小。
4. 缩短非必要长丝带或尾饰，避免核心主物被迫缩小。
5. 仅在120px下与同组参考并排校准，不新增74px或96px验收要求。

## 6. 青鸟传音专项设计

### 内容构成

- 一只青蓝绿色小青鸟，奶油白胸腹，少量青蓝暗部。
- 三分之四侧面朝右，以紧凑展翅表现传递消息。
- 鸟喙衔短绳，连接奶油白折叠信笺；信笺以浅桃小花封签。
- 不添加文字；花封签作为识别性点缀，不扩展为大簇花枝。
- 主次设计意图约为青鸟70%、信笺30%，并非已测定的像素面积比例。
- 两翼前后关系、喙与绳的连接、信笺折叠结构必须合理。
- 羽毛概括成少量大羽片，保留两根简洁尾羽，避免密集羽纹、绒毛和珠串。

### 120px判断重点

鸟必须先于装饰被识别；信笺不能缩成不明色块；短绳不应变为突兀杂线。两翼、身体和尾羽不能互相粘连到无法理解结构。

## 7. 新图标设计流程

1. **明确功能**：写一句“玩家点击后做什么”，找出一个主要物件或动作。
2. **确定组合及参考角色**：按composition-layout.md绑定图层尺寸、底框/名称板、可见区域、层级及摆放；再区分主体、界面和画风依据。
3. **设计轮廓**：一个主物，必要时增加一至两个辅助语义物件；在组合可见区域内确保功能区分，避开名称板对关键符号的遮挡。
4. **封存配色计划**：按palette-workflow.md单独列出画风与配色参考，运行start；不把青绿、白花或金边作为系列默认。随后**应用统一美术**：使用左上主光、柔和色块、同组描边与适量金色。
5. **高清创作或编辑**：保留必须不变的主体、颜色及结构，针对具体问题修改。
6. **尺寸与定位**：按已固定摆放将内容坐标落实到PNG留白，UI额外补偿归零，再按composition-layout.md导出并核对双尺寸关联；不紧裁或自动居中。
7. **透明边缘清理**：检查游离像素、残余背景和光晕，保留正常抗锯齿。
8. **120px验收**：在浅、深底上，与固定的10张同组正式参考按实际120px画布分行对照，待验图另列；选图与显示方式遵循qa-120.md，同时检查当前任务图标的完整组合。
9. **针对失败项修正**：逐项核销实际结果，关键失败不判合格；同一目标两次无改善时按delivery-review.md改变方法，避免无目的反复重绘。
10. **复查及交付**：按palette-workflow.md完成第二遍复查及最终关卡，缺项不通过；按delivery-review.md分别记录文件、120px视觉、用户接受和工程状态。提供高清PNG、同版本120pxPNG、对照及通过/未验证说明。

### 透明边缘注意事项

低透明度像素不一定是噪点，可能是正常抗锯齿或合法半透明材质。不要把整张图粗暴二值化，也不要填实半透明部分。

连通组件分析可帮助发现孤立噪点，但不是“只有一个组件才合格”：新图标可能包含合法分离物件。应结合设计语义和画面检查，再决定清理范围。

## 9. 120px验收表

| 检查项 | 通过条件 | 不通过时处理 |
|---|---|---|
| 功能识别 | 分别核对主物可辨、具体入口可区分、名称依赖；按本次辨识目标判定，不用主物识别替代功能通过 | 放大关键物、删装饰，必要时改语义构成并复查本批图标关系 |
| 主体大小 | 与同组并排无明显忽大忽小 | 等比例调整或收紧非必要附件 |
| 重心 | 在固定完整组合内无明显偏坠、偏侧 | 区分图内留白与UI补偿，按组合配置定位 |
| 结构 | 前后遮挡、连接和透视合理，名称板不破坏关键轮廓 | 在锁定主体与摆放的条件下修正局部 |
| 光源 | 左上亮、右下暗的总体逻辑一致 | 修正冲突高光与暗面 |
| 描边 | 整组视觉粗细接近，无突兀黑粗边 | 定向修正，不叠黑边补救 |
| 噪点与杂线 | 120px下无明显游离点、莫名线条 | 结合透明通道与结构清理 |
| 边缘 | 浅、深底均无明显白边、光晕或锯齿 | 修正抗锯齿或残余背景 |
| 安全区 | 默认高清四边至少102px透明；任务布局例外通过绑定几何合同另验允许边界 | 不擅自居中或缩小；分别保留默认结果与任务结果 |
| 文件 | 高清1024×1024、使用图120×120，RGBA透明PNG | 重新导出 |

对照底色可沿用浅色 #F4EDE1 与深色 #293139。它们是检查用底色，不是交付图标背景。

显示对照时，单个图标画布保持120×120；聊天或浏览器可能缩放整张预览，应按原始图片像素判断。

## 10. 验收结论的边界

- **可客观确认**：文件尺寸、RGBA通道、包围框、安全留白、是否存在独立像素组件。
- **需要视觉判断**：主体视觉重量、完整组合适配、功能识别、受光一致性、描边观感、结构和材质是否自然。
- **不能仅靠生成结果保证**：逐像素等宽描边、绝对无噪点、玩家必然一眼理解、最终上线质量。
- **本轮未验证**：游戏引擎导入、图集打包与压缩、真机显示。
- 只有图片文件和120px视觉检查通过时，应记录为“资源与120px检查通过，接入游戏后的验收未验证”，不直接写“上线验收通过”。

### 色彩与派生导出约定

新交付默认先将组合定位落实到完整1024画布，再在同一色彩空间缩放到120，默认Pillow LANCZOS；其他支持算法须明确记录并同参数验证，不紧裁铺满。使用尺寸精确整数平移与高清小数位移冲突时，按[输出与双尺寸关联](composition-layout.md#输出与双尺寸关联)记录例外、主尺寸目标位移与明确取整方法，由检查器计算另一尺寸及误差，不伪称直接派生。check_icon.py报告源图/预览SHA-256、Pillow版本与算法；普通任务也必须提供布局绑定并通过UI额外偏移为0的检查。精确复现失败可能源于旧工具版本或导出流程差异，不能单凭此结论断定图像错配；先核对导出来源，无法复现时登记未验证，不静默改算法以求通过。

PNG位深以源文件IHDR为准。sRGB检查保守区分明确声明、ICC待验证、缺失和冲突；新交付运行--require-srgb，脚本接受无冲突的合法PNG sRGB声明。有效ICC不等于已证实sRGB；严格模式不能确认的ICC流程需色彩管理工具另行验证并记录例外，不能改名或忽略失败来凑通过。sRGB元数据符合不证明来源像素经过正确转换。

按[色彩空间与导出记录](color-space-export.md)实际执行collect、export或只读audit、verify：保留原始文件并采集声明；有效RGB ICC以真实源/目标配置转换并复验；未知默认停止，可明确保留未知，或为新候选记录sRGB工作假设。假设不构成来源通过，指派标签不是色域转换。已确认图标走只读audit，不改色、不重写；原用户接受不因来源未验证被撤回。自由文字报告不授予当前色彩通过，具体支持范围和未支持处理链见专项流程。
