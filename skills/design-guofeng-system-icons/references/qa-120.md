# 固定120px对照验收

批量任务可按 [批次清单与只读验收](batch-review.md) 运行对照编排，保留每格120px、固定10参考和候选另列。生成图及索引只证明编排，视觉意见仍按本文逐项实际检查，并绑定当前图片、参考与控制卡版本。

## 对照条件

1. 固定当前案例的10张同组正式参考及其版本；待验图、修改前图不计入这10张。按reference-library.md的选图规则兼顾相关性与类型覆盖，不用重复图或局部裁切凑数。可用正式参考不足10张时使用全部可用参考并报告缺口，不虚称达到10张。修改前后沿用同一组，不为得到通过结论而换参考。
2. 将修改前、修改后及参考均从完整画布等比例导出120×120；保持透明留白，不分别紧裁后自动铺满。记录缩放方法并保持一致。
3. 在浅底 #F4EDE1 与深底 #293139 各制作一组对照，每组10张参考可排为5列×2行，待验图与修改前图另列。单个图标显示区域严格120×120，间距一致；标注参考ID与版本，文字置于图标外。必要时分页或拆成多个面板查看，禁止为容纳全图而把每张缩到120px以下。不能以放大的预览冒充120px观察。
4. 实际查看两组对照。工具无法按该显示尺寸查看时标记未验证。仅以120px作视觉验收；高清文件可用于定位缺陷和硬规格测量，不新增其他视觉尺寸门槛。

## 逐项记录

先按控制卡指定体量、描边、明暗各自的主要参照，限定用途参考不能自动成为所有项目的标尺。实际查看全部10张参考与待验图后，每项记通过／失败／未验证，并给一条观察依据，避免只写“整体一致”。记录最接近的参考和明显偏离项；不同材质、构图之间比较画风与视觉重量，不要求相同内容、色彩或造型。

| 项目 | 检查内容 |
|---|---|
| 功能识别 | 分别判断主物识别、具体入口区分及是否依赖名称；物品可辨不能代替功能通过 |
| 视觉重量 | 主体体块、实色面积、轮廓疏密与参考是否协调；几何包围框相同不代表等大 |
| 重心与结构 | 重心是否偏移，连接与遮挡是否明确，物品是否粘连 |
| 明暗与材质 | 对比强弱是否协调，材质分组是否清楚，是否出现厚重金属或碎亮点 |
| 光源与描边 | 物体表面是否符合左上受光，外内线粗细与存在感是否协调 |
| 边缘与噪点 | 两种底色下有无明显残底、白边、游离点或异常线 |
| 保持项 | 用户要求保留的构图、比例、配色和关键元素有无漂移 |

## 跨物件与关系对照

跨物件批次另按 [跨物件画风验收](style-transfer-review.md) 检查代表组、全部候选和易混淆组。先看仅标ID的图，再核对名称与点击目的；审阅者已知功能时必须注明，不能称玩家盲测。

关系记录复用逐项记录，增加：组ID／关联项目ID、主参照及借鉴项、差异理由（材质允许／功能必须／无依据）、观察位置、偏差类别（画风／语义／结构）、建议改动、保持项与复查方法。只有数量、像素或文件关联可测量时才写实测；画风与辨识意见标为视觉判断，不虚构相似度分数。位置采用图标内上/中/下或面板格坐标，避免只有“更协调”。

## 结论边界

- 1024尺寸、PNG真实位深、透明通道、安全区、sRGB标识与120派生关联由check_icon.py分别报告；视觉项必须实际看图。记录高清/120哈希及缩放算法，不能只凭两个文件分别合格就认为对应。
- 失败项修正后复查该项及保持项，并继续使用原对照条件。
- 输出记录：案例ID、技能版本、前后图与参考路径/版本、背景与缩放方式、各项结果、未验证项、用户确认范围。
- 只有所有必需项已检查通过，才能标注本次120px验收通过；不能据此声称引擎、压缩、真机或线上验收通过。

## 交付记录与实际UI

逐项保留判断依据与观察位置；“改善”“可接受”“用户满意”不能替代通过/失败/未验证。明确接受的差异登记为用户例外，不删除原失败项。误报过的项或连续失败项按delivery-review.md复查后才能再次称通过。

有实际UI时，在既定120px入口区域补检查背景、名称、相邻入口与红点/状态遮挡；没有时记UI未验证，不阻塞资源部分交付。静态UI通过不代表引擎/真机通过。交付时分别说明文件、120px视觉、用户接受、UI和工程五种状态。
